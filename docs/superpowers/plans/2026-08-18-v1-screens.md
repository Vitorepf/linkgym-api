# V1 screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship every v1 screen locked in the spec — 8 of the personal, 16 of the student — so the daily loop runs on the phone: publish → Hoje → session → fio → attention → comeback.

**Architecture:** One Expo binary, two stacks after `/v1/me`. The API owns truth (prescription, ofensiva, attention, PRs). The phone owns unsynced sets. Navigation is React Navigation (`native-stack` + `bottom-tabs`); `StudioHome.tsx` is deleted once routing exists. JSON keeps English keys (`studio`, `load_kg`); the chrome never prints LinkGym, Time, or Estúdio — only `studio.name` (seed: `Fred`).

**Tech Stack:** Expo SDK 54, TypeScript, StyleSheet + `src/theme.ts`, Reanimated 4, Go 1.26, Postgres 16, goose SQL. No Tamagui, NativeWind, styled-components, expo-router, or new migrations unless a task names a numbered file.

## HTTP contract

All JSON snake_case. Bearer on everything except `/health`, `/v1/auth/code`, `/v1/auth/verify`. Errors: `{ "error": "<code>" }` matching `internal/auth/errors.go` style.

Auth already shipped:

- `POST /v1/auth/code` `{ phone, invite_code? }` → `{ ok, dev_code?, studio? }`
- `POST /v1/auth/verify` `{ phone, code, invite_code? }` → `{ token, person, studio }`
- `GET /v1/me` → `{ person, studio, onboarding_complete, commitment_complete, debut }`
- `POST /v1/auth/logout`

Extend `person` with `role` (already). Extend `studio` with optional `logo_url`.

`GET /v1/me` extra booleans (computed, not columns):

- `onboarding_complete` — `bonds.onboarding` has `experience`, `days_per_week`, `pain`
- `commitment_complete` — `bonds.commitment_at IS NOT NULL`
- `debut` — zero `workout_sessions.finished_at` for this person+studio

### Student

`GET /v1/today`

```json
{
  "studio": { "id": "", "name": "Fred", "accent_color": "#ec3013" },
  "person": { "id": "", "name": "Vitor" },
  "readiness": { "score": 78, "energy": 4, "soreness": 2, "sleep": 4, "label": "Pode ir com carga" },
  "streak": { "current_count": 0, "protector_available": true },
  "xp_total": 0,
  "prescription": {
    "id": "",
    "name": "Treino A",
    "for_date": "2026-08-18",
    "minutes": 52,
    "items": [
      {
        "id": "",
        "exercise_id": "",
        "name": "Supino",
        "position": 1,
        "planned_sets": 3,
        "planned_reps": "8-12",
        "load_kg": 40,
        "rest_seconds": 90,
        "notes": "",
        "video_url": null
      }
    ]
  },
  "banner": { "text": "Fred publicou o Treino A", "kind": "published" },
  "coach_line": "Supino em 40. Técnica, não ego.",
  "debut": false,
  "comeback": null
}
```

`comeback` when open: `{ "id": "", "minutes": 9, "coach_line": "Sem culpa. Nove minutos e você está de volta." }`.

No prescription: `prescription` is `null`, CTA copy “Hoje não tem ficha. O Fred publica aqui.”

`PUT /v1/today/readiness` `{ "energy": 1-5, "soreness": 1-5, "sleep": 1-5 }` → same `readiness` object. Score = `round(((energy + (6-soreness) + sleep) / 15) * 100)`. Labels: `>=70` `Pode ir com carga`; `>=40` `Hoje não é dia de PR`; else `Versão leve`.

`POST /v1/sessions` `{ "client_id": "<uuid>", "prescription_id": "" }` → `{ "id", "client_id", "started_at" }` (idempotent on `person_id+client_id`).

`POST /v1/sessions/{id}/sets`

```json
{
  "client_set_id": "<uuid>",
  "prescription_item_id": "",
  "exercise_id": "",
  "swapped_from_exercise_id": null,
  "set_index": 1,
  "reps": 10,
  "load_kg": 40,
  "rest_seconds": 90,
  "effort": 2,
  "performed_at": "2026-08-18T12:00:00Z"
}
```

`effort` on a set is optional. Session effort is 1=fácil, 2=no ponto, 3=difícil.

Idempotent on `(session_id, client_set_id)`. If the row exists, return 200 with the stored row (client already won).

`POST /v1/sessions/{id}/swap` `{ "from_exercise_id", "to_exercise_id" }` → `{ "ok": true }`. Inserts `session_alerts.kind = exercise_swap`. Does **not** break ofensiva.

`POST /v1/sessions/{id}/finish` `{ "effort": 1|2|3 }` → `{ "streak", "xp_gained", "xp_total", "records": [ { "exercise_name", "load_kg", "previous_kg" } ], "badge_keys": [] }`.

Finish rules:

- `finished_at = now()`, `synced_at = now()`.
- XP: `10` for finish (`reason=session`); plus `25` per new PR (`reason=pr`).
- PR: if `load_kg` of a set > `personal_records.load_kg` for that person+exercise (or no row), upsert PR.
- Ofensiva: if `for_date` of the prescription counts as fulfilled, `current_count += 1`, `last_fulfilled_on = for_date`.
- Alert `session_synced`.
- Debut finish awards badge `estreia`.

`GET /v1/progress` → `{ "streak", "xp_total", "league": [ { "name", "xp_total", "me": true } ], "badges": [ { "badge_key", "earned_at" } ], "readiness_week": [ { "for_date", "score" } ] }`. League = students of the active Time, ordered by XP desc, max 10.

`GET /v1/records` → `{ "items": [ { "exercise_name", "load_kg", "reps", "achieved_at", "history": [ { "load_kg", "achieved_at" } ] } ] }`. History may be a single current row in v1 (no extra table); do not add a history table.

`PUT /v1/onboarding` `{ "experience": "never"|"before"|"training", "days_per_week": 2-6, "pain": false }` writes `bonds.onboarding`. If `pain=true`, insert `attention_items.reason='pain_flag'` rank 1 for today (still cap 3).

`PUT /v1/commitment` `{ "days_per_week": 2-6 }` sets `commitment_text` to `"{n} dias"` and `commitment_at=now()`.

`POST /v1/comebacks/{id}/complete` sets `completed_at`. Does not wipe PRs.

### Personal

`GET /v1/owner/home`

```json
{
  "greeting": "Bom dia, Fred",
  "student_count": 3,
  "fio": { "prescribed": 3, "done": 0, "week": [ { "for_date": "2026-08-18", "done": 0, "prescribed": 3 } ] },
  "attention": [ { "id": "", "person_id": "", "name": "Jose", "reason": "student_stopped", "decision": "Mandar a retomada de 9 minutos", "rank": 1 } ],
  "unread_returns": 0
}
```

`GET /v1/owner/attention` → `{ "items": [ ...same as attention..., "applied": false ] }` length ≤ 3.

`POST /v1/owner/attention/{id}/apply` → `{ "ok": true }`. For `student_stopped`, upsert `comebacks` for that bond (today as `missed_on` if none open) and mark a local applied flag: store `payload` on the attention row is not a column — set `reason` unchanged and insert `session_alerts.kind=student_stopped` with `read_at=now()` meaning handled, **or** delete that day’s attention item after apply so the queue shrinks. **Decide: delete the attention row after apply.** The 90s screen counts `3 - remaining`.

`GET /v1/owner/week?from=YYYY-MM-DD` (default Monday of current week) → `{ "items": [ { "person_id", "name", "adherence": "2/3", "suggested": "+2,5 kg no supino", "selected": true } ] }`. Suggestion v1: if last session effort=1, `+2.5 kg` on first item; if effort=3, `manter`; if missing two prescribed days, `versão curta`. No IA.

`POST /v1/owner/week/approve` `{ "person_ids": [] }` publishes next `for_date` (tomorrow) from the current modelo of each selected person using `publish` rules. Returns `{ "count": n }`.

`GET /v1/owner/students/{id}` → student card: last session effort, last loads, streak, suggested one action (`renew` | `nudge` | `keep`).

`GET /v1/models` → list `{ id, name }`. Seed has `Treino A`.

`GET /v1/models/{id}` → items with `starter_load_kg`.

`POST /v1/models/{id}/draft-from-last` `{ "person_id" }` → `{ "draft_id", "items": [ { "exercise_id", "name", "planned_sets", "planned_reps", "load_kg", "load_source" } ] }` where `load_kg` is that person’s last set or starter. Draft is a `prescriptions` row `status=draft` for `for_date=tomorrow`.

`PATCH /v1/prescriptions/{id}/items/{item_id}` `{ "load_kg", "planned_sets", "planned_reps" }` only if status=draft. Sets `load_source=manual`.

`POST /v1/publish` `{ "prescription_id": "", "also_person_ids": [] }`. Sets the draft to `published`. For each extra person, clone **structure** from the modelo, fill `load_kg` from that person’s history or starter, never from the first person’s numbers. Test: Vitor 40, Huan 22.5.

`GET /v1/owner/returns` → unread `session_alerts` of kind `session_synced` + latest session summary (effort, PRs).

`POST /v1/owner/returns/{alert_id}/apply` `{ "bump_kg": 2.5 | 0 | -2.5 }` writes next draft loads and `read_at=now()`.

## Navigation

```
Access                    // not logged in
  └─ D0 stack             // student && !onboarding_complete
        SobreVoce → Pronto
  └─ Student tabs         // student && onboarding_complete
        Hoje | Progresso | Perfil
        stack from Hoje: Ficha, Session (Série/Vídeo/Descanso), Feito, Recorde, Estreia, Compromisso, Retomada
  └─ Owner tabs           // role owner
        Painel | Semana | Fichas
        stack: Atenção, Aluna, Base, Ajustar, Publicar, Retorno
```

Session is a modal stack: Série ↔ Vídeo ↔ Descanso, then Feito, then optional Recorde if `records.length > 0`.

Default route after login:

- owner → Painel
- student + comeback open → Retomada
- student + debut + no finish → Estreia then Hoje
- else → Hoje

A6 “Entrada sem fricção” is this default. No widget screen.

export type QueuedSet = {
